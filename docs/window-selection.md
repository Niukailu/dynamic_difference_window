# 按最终贡献选窗与分配宽度（2026-09-21）

本轮用户腾空 8 张 B300 后，完成了候选分片、多个轮位置并行搜索和大窗口对照。目的在于检验原选窗假设，提升保留路径的聚集权重，而不是把 GPU 利用率当作结果指标。所有修改均在 `gpt-6-astra`，未修改 master。

## 已得到正向结果：按端点贡献分配新增自由位

原来的嵌套扩窗根据当前分布的矩等信息选位。它能增加保留的总质量，但没有直接衡量新增路径最终能否到达指定端点。新的流程在候选窗口上计算前向权重与端点后向权重，用 `sum(F × H)` 精确评价每个新增位对最终端点的贡献。每次比较所有轮的单比特扩展，保留最好的完整重放结果，再基于新计划重新评分。

这是对“窗口在哪些轮加宽”和“具体释放哪些位”的联合贪心选择，不是全局最优算法，也没有把不同计划上测到的独立增益相加。当前排序依据为端点增益；尚未实现按实测耗时或显存成本惩罚的优化目标。

SIMON64 线性 25 轮，输入 `(0x44400, 0x1000)`、输出 `(0x1000, 0x44400)`：

| 方案 | log₂ 端点权重 | 各轮状态数之和，相对原均匀 w15 | 最大稠密单状态 |
|---|---:|---:|---:|
| 后验优化后的 w14 起点 | −64.263484114764 | 25.01% | 2 GiB |
| 原规则均匀扩为 w15 | −64.219929426352 | 100% | 8 GiB |
| 自适应增加 3 个自由位 | **−64.197909757869** | **34.10%** | 8 GiB |
| 保留自适应选位，再均匀扩为 w15 | **−64.193067174915** | 100% | 8 GiB |
| 自适应增加第 4 个自由位 | −64.182130202697 | 43.18% | 16 GiB |

前三步分别是第 12 轮增加 bit 0、第 13 轮增加 bit 26、第 11 轮增加 bit 26。仅这三轮从 w14 变为 w15，权重比起点增加约 **4.65%**。第四步给第 12 轮增加 bit 24，使其成为 w16，同时增加了最大状态规模。

表中的状态数之和为 `Σ |W_r| |W_(r−1)|`，是可复算的规模指标，**不是测得的运行时间或隐式后端显存**。初始状态只有一个值；起始两轮窗口本来就小于配置宽度。相同宽度不代表相同窗口：不能把原均匀方案的分数当作所有 w15 方案的上限。后一项同宽度对照恰好说明位的选择也影响结果。

## 被检验但尚未带来收益的假设

### 同一轮同时更换两位

`joint-refine` 扩大两个自由位，用 GPU 计算每对位的四个后验分区。固定其中两位即可同时评价双比特替换；四个分区独立累加，避免从大数中减小数。新增位组合可按 `--shard / --shards` 分到不同卡。

在 w14 起点上检查了轮 4、6、8、13、14、15、16、17、18，未发现严格改善。轮 13 的 153 个新增位对由 8 卡分片完成；其他轮各自检查全部新增位对。这里只检验一轮内的双位邻域，不代表相邻轮联合改动也没有收益。

### 用两位异或关系代替固定坐标位

一个状态主要落在 `00/11` 的分布中，单坐标窗口只能覆盖其中一半；同样大小的仿射窗口可以覆盖全部。因此不能先验认定坐标窗口总是合理。

`affine-refine` 在原窗口上增加一个位，再施加 `x_i XOR x_j = c` 约束，使状态总数保持不变。这个仿射窗口可精确拆成两个互不相交的坐标窗口，分别完整重放再相加，不需要改写 CUDA 转移的状态表示。它只覆盖“一轮、一条二元 XOR 约束”这一窗口族，尚非通用仿射子空间搜索。

本轮对自适应搜索所经过的四个计划分别检查全部 25 轮，均未发现这种等状态数替换优于原窗口。结果限制了这个局部假设的收益，不能据此否定高阶线性关系、多个轮同时改变或多个互补窗口。

## GPU 改变了哪些可行的算法选择

- 端点后验分区一次评价很多候选，不再为每一个固定值单独完整搜索。
- 以卡为单位分配候选组合或轮位置，避免用多卡重复搜索同一个候选。
- 单轮优化只需要一个后缀消息：新增 `backward_suffix` 将其保留在 GPU 上，避免把整条反向消息链搬回 CPU。
- 大窗口仍用于独立对照；实际提升来自窗口和路径选择，不能仅由利用率或窗口宽度判断。

还值得做的两项改变是：跨轮联合选窗，以及直接优化相对已有路径集合的新增权重 `P(B \ A)`。后者的非负二状态动态规划方案见[算法方向](algorithm-directions.md)，本轮尚未实现。它们需要新的正确性验证，不能由当前单窗口实验宣称有效。

## 使用

```bash
# 单轮双比特替换；8 卡时每卡使用不同 shard
./target/release/ddw joint-refine PLAN.jsonl --round 13 \
  --shard 0 --shards 8 --device 0 --memory-gib 128 --output joint-0.jsonl

# 等大小异或窗口 + 每个新增位的端点贡献；保存最佳扩展的完整重放
./target/release/ddw affine-refine PLAN.jsonl --round 12 \
  --device 0 --memory-gib 192 --output profile.json

# 每一步评价全部轮，再选择一个新增位；Python 仅负责启动 Rust 进程
python tools/profile_windows.py PLAN.jsonl --binary ./target/release/ddw \
  --devices 0,1,2,3,4,5,6,7 --memory-gib 192 --iterations 3 --output adaptive-run
```

工具拒绝覆盖现有输出。自适应协调器检查最佳重放仍以原指定端点为峰值；若峰值端点变化，明确停止，不悄悄改变优化目标。自适应剖面的内存检查采用实际相邻窗口的最大状态规模，不再以所有轮都达到最大配置宽度估计非均匀计划。

## 大窗口对照

独立的 SIMON128 差分 w19 扩展完成 45 轮，端点权重从此前的 `−127.574478192099` 提高到 **`−127.442713104012`**，约增加 **9.56%**；没有据此宣称突破 46 轮。两条嵌套扩展起点在这一实验中得到相同结果，记录见[当前 w19 结果](../results/best/simon128-w19-endpoint-expanded.jsonl)。它属于增加窗口预算的结果，应与上面改变选窗规则的对照区分开来。

SIMON64 的 w20 单计划为 `−64.118916097979`，与反射路径集合去重后的并集为 **`−64.104083953419`**，是本轮总体最好值；仍未达到 `−64`，没有增加有效轮数。另一条 w19 路线与旧对称计划的四集合容斥为 `−64.105220930693`。见[最佳并集](../results/best/simon64-linear25-dedicated-union.json)；全部 7 份新并集均另用 Python 标量求和复核。

## 验证

- SIMON/SIMECK × 差分/线性、四种后缀长度：所有双位四分区评分与逐候选直接局部重放核对。
- Rust CLI 的双位搜索、异或窗口、新增位剖面和完整候选重放，由独立 Python CPU 转移核对；同时回归已有镜像、后验、隐式矩阵与容斥流程。
- 被选中的窗口另外完整正向重放，检查固定端点得分；自适应每一步重新计算前后向消息。
- FP64 数值回归，不是严格区间算术证明。
