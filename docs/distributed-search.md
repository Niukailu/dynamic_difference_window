# 跨卡动态选窗与 w17 实验（2026-09-21）

继续使用共享的 8 张 B300，没有独占、停止或调整其他训练任务。工作基于 `aa812ac`，保持 FP64 和论文的转移模型。

## 让多卡容量用于更大的搜索

原多卡实现只能重放已有计划。本次增加跨卡嵌套扩窗：各卡分别计算位边缘质量、加权位质量及活跃位贡献，只向主机传回 `4 × word_bits` 个 FP64 数值，然后合并选择窗口。SIMON128 每卡每轮约 2 KiB 的选窗统计；概率矩阵仍留在 GPU。每一轮的新窗口包含指定参考窗口，所以沿同一输入传播时不会主动删除参考计划中的路径。

w16 的满矩阵为 32 GiB，w17 为 **128 GiB**。八卡按行分片后，每张 w17 矩阵每卡 16 GiB；还需要输出矩阵、陪集缓存和工作区。本批运行每卡内存池上限 60 GiB。

## 实际结果

| 模式与轮数 | 原 w16 的 log₂ 峰值 | 新 w17 的 log₂ 峰值 | 概率提升 |
|---|---:|---:|---:|
| SIMON128 差分 45 轮 | −127.761229169588 | **−127.725579424791** | 约 2.50% |
| SIMON128 线性壳 46 轮 | −131.351198854460 | **−131.290195661** | 约 4.32% |

差分输入仍为 `(0x1000, 0x4440)`，45 轮端点仍为 `(0x444040, 0x100000)`。差分超过 2^-128 的余量由 0.23877 bit 增至 0.27442 bit；没有新增轮数。线性 46 轮仍低于 2^-128。

两次扩窗完整运行各约 11 秒（共享环境下单次记录，不是独占性能基准）。逐轮检查参考端点的概率不下降、峰值不超过保留质量、质量不随轮数增加。

- [差分 w17](../results/simon128-diff-w17.jsonl)，[coset 复核](../results/simon128-diff-w17-coset-check.jsonl)：全部 45 轮 log₂ 峰值最大误差 2.8422e-14。
- [线性 w17](../results/simon128-linear-w17.jsonl)，[coset 复核](../results/simon128-linear-w17-coset-check.jsonl)：全部 46 轮最大误差 1.4211e-14。

复核同时反转卡号分配。coset 使用原子陪集求和与消元查询，主实验使用子组归约与仿射查表；两者共享基构造，不是完全独立的密码分析程序。

## 更便宜的候选评估

新增 `Engine.retained_mass`，无需生成候选的完整输出矩阵。设一行的转移为均匀仿射空间 `b + A`，目标窗口为 `t + T`，向 T 外部位投影为 π，令 `k = dim π(A)`。对于右分支值 r：

- 若 `π(b ⊕ r ⊕ t)` 不属于 `π(A)`，落入目标窗口的质量为零；
- 否则落入比例恰好为 `2^-k`。

因此只需对满足投影约束的输入概率求和，再乘 `2^-k`。实现将投影约束编译成分块 XOR 查表，按输入块归约，不生成输出、不分配输出陪集缓存，也不进行候选的跨卡重排。

SIMON64 w15，第 12 轮同一固定输入与目标，GPU 0，预热后五组交替测量：

| 候选质量评估 | 中位耗时 |
|---|---:|
| 生成完整输出后求和（输出缓冲复用） | 29.43 ms |
| 投影约束直接求和 | **6.07 ms** |

此阶段加速 **4.85 倍**。两种方法的归一化质量分别为 1556.716705026710 / 1556.7167050267099（输入按峰值归一化，因此该数值不是绝对概率）。原始数据：[projected-mass-benchmark.json](../results/projected-mass-benchmark.json)。此加速不能当作完整搜索的加速比。

w17 四候选完整搜索从 26.31 秒降至 16.06 秒，逐轮峰值完全一致。这两次完整运行没有重复交替，因此只作辅助记录，不用来推断稳定加速比。

## 候选更多不一定更好

对相同 w16 参考逐轮扩到 w17：

| 策略 | 差分 45 轮 log₂ 峰值 |
|---|---:|
| 原评分选一个窗口 | **−127.725579424791** |
| 四个局部候选，按下一轮峰值选择 | −127.725579424791 |
| 四个局部候选，按下一轮质量选择 | −127.725688644422 |

后者略差。局部总质量和最终指定轮的峰值不是相同目标，当前结果不支持把更多候选作为默认配置。主结果采用一个候选。候选窗口均包含 w16 参考，但不保证包含另一条 w17 搜索历史。

单卡 CLI 的 `--lookahead-objective mass` 也改用投影公式；原 SIMON64 w10 八候选实验复跑后，23 轮峰值误差不超过 7.1055e-15。17 项测试通过，新增覆盖两种密码、两种模式、多个字长及 0–17 位右窗口的投影质量，以及分布式评分、候选评估不修改输入、两种交换方式的多轮完整矩阵对照。

## 复现

```bash
python -m ddw.multigpu results/simon128-diff-w16.jsonl --width 17 \
  --memory-gib 60 --output results/my-difference17.jsonl
python -m ddw.multigpu results/simon128-linear-w16.jsonl --width 17 \
  --memory-gib 60 --output results/my-linear17.jsonl
python scripts/check_results.py results/my-difference17.jsonl
python -m ddw.multigpu results/my-difference17.jsonl --kernel coset \
  --devices 7,6,5,4,3,2,1,0 --memory-gib 60 --output results/my-crosscheck17.jsonl
python scripts/check_results.py results/my-crosscheck17.jsonl \
  --reference results/my-difference17.jsonl --tolerance 1e-10
python scripts/benchmark_candidate_mass.py results/simon64-diff-w15.jsonl \
  --device 0 --output results/my-mass-benchmark.json
```

`check_results --reference` 验证数值相等，不能拿 w16 和 w17 直接作等值回归；w17 自带逐轮参考端点记录，默认检查包含关系带来的概率不下降。

## 后续方向

目前没有硬件上限证据。全宽 w18 的单张矩阵为 512 GiB，八卡两张分片仅概率矩阵就需每卡 128 GiB，超过本次共享环境的剩余显存；没有强行运行。w16 到 w17 的小幅收益表明，单纯扩大稠密矩阵的性价比开始下降。

更值得研究的是跨多轮评价窗口、针对目标端点的反向约束和剪枝，以及能够验证误差界的稀疏或分块表示。现有快速质量评估降低了探索候选的成本，但没有解决长程目标选择问题。这些方向尚未实现或验证，不能据此声称进一步改进结果。
