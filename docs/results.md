# GPU 重构实测（2026-09-21）

所有实验位于 `gpt-6-astra` 分支，历史基准来自仓库已有日志。硬件为共享的 NVIDIA B300；没有独占 GPU，没有修改其他训练进程。以下“概率”均为论文转移模型下的 FP64 路径聚集估计，不是对真实密码长轮数概率的直接穷举验证。

## 算法效率

SIMON64 差分、输入 (0,1)、宽度 15、23 轮，固定完全相同的窗口计划，在 GPU 3 上依次运行。三个版本均已修正消元问题并预计算基向量的位压缩坐标。

| CUDA 转移算法 | 23 轮时间合计 | 相对陪集算法 |
|---|---:|---:|
| scatter：逐输入枚举输出 | 108.922 秒 | 49.25 倍 |
| gather：逐输出枚举前像 | 23.226 秒 | 10.50 倍 |
| coset：陪集聚合后查询 | **2.211 秒** | 1 倍 |

这里包含基构造、转移、统计及内存池清理，使用同步墙钟；固定计划不重新选窗。逐轮 log₂ 最大概率的跨内核最大误差 1.4211e-14。共享 GPU 上单次对照不能替代独占、重复运行的性能基准，也不能将 49 倍称为相对原 CPU 程序的加速比。

原始记录：[coset](../results/kernel-benchmark/coset.jsonl)、[gather](../results/kernel-benchmark/gather.jsonl)、[scatter](../results/kernel-benchmark/scatter.jsonl)。复现：

```bash
python scripts/benchmark_kernels.py results/simon64-diff-w15.jsonl \
  --device 0 --output-dir results/my-kernel-benchmark
python scripts/check_results.py results/my-kernel-benchmark/scatter.jsonl \
  --reference results/my-kernel-benchmark/coset.jsonl --tolerance 1e-10
```

宽度 16 的 SIMON128 差分 45 轮，逐轮记录的时间合计 44.26 秒；这批较早日志的计时不含每轮末尾内存池清理，不能直接与上表当作严格端到端对照。后续 CLI 已将该清理计入，并记录整个搜索墙钟。

## 同输入、同输出的概率改进

下表新结果采用嵌套扩大旧窗口。所有列均为 log₂ 概率；数值越大越好。

| 场景 | 轮数 | 历史 w14 | 新 w15 | 新 w16 |
|---|---:|---:|---:|---:|
| SIMON128 差分 | 44 | -126.665612 | -125.912010 | **-125.761229** |
| SIMON128 差分 | 45 | -128.665612 | -127.912010 | **-127.761229** |
| SIMON128 线性壳 | 45 | -124.949611 | 本次最终版未跑 | **-124.560858** |
| SIMON128 线性壳 | 46 | -131.751124 | 本次最终版未跑 | **-131.351199** |
| SIMON64 线性壳 | 24 | -62.398117 | **-62.269957** | 未跑 |
| SIMON64 线性壳 | 25 | -64.398116 | **-64.269955** | 未跑 |

SIMON128 差分的输入为 `(0x1000, 0x4440)`。44 轮输出为 `(0x100000, 0x44040)`，45 轮输出为 `(0x444040, 0x100000)`。宽度 16 的 45 轮估计超过 2^-128，较旧日志同轮同端点改善约 0.9044 bit（约 1.87 倍），按论文采用的判据，将该模型下的差分区分器从 44 轮推进至 **45 轮**。超过随机基准的余量约 0.239 bit，仍需要谨慎的独立密码学验证。

宽度 15 的 45 轮结果额外用 gather 内核重放完整窗口计划，全部 45 轮 log₂ 最大概率与 coset 的差异不超过 1.4211e-14。宽度 16 使用相同已测试的算法，但未单独用慢内核完整复跑。每个嵌套运行的每一轮均检查了旧端点概率没有下降、总保留质量没有增加。

SIMON128 线性壳输入为 `(0x4000000000000044, 0x1)`；45 轮输出为 `(0x100000000000000, 0x4440000000000040)`。46 轮仍低于 2^-128，因此目前不能声称线性壳增加了一轮。

主要证据：

- [SIMON128 差分 w15](../results/simon128-diff-w15.jsonl)、[另一内核复核](../results/simon128-diff-w15-independent.jsonl)、[w16](../results/simon128-diff-w16.jsonl)
- [SIMON128 线性 w16](../results/simon128-linear-w16.jsonl)
- [SIMON64 线性 w15](../results/simon64-linear-w15.jsonl)

复现最强差分结果时，直接固定已保存的窗口计划，可避免浮点平局导致自适应选窗变化：

```bash
python -m ddw --device 0 --word-bits 64 --left 0x1000 --right 0x4440 \
  --width 16 --rounds 45 --memory-gib 74 \
  --replay-windows results/simon128-diff-w16.jsonl \
  --output results/my-simon128-w16.jsonl
python scripts/check_results.py results/my-simon128-w16.jsonl \
  --reference results/simon128-diff-w16.jsonl --tolerance 1e-10
```

## 放开窗口启发式的探索

SIMON64、输入 (0,1)、w10、23 轮，修正后的转移算法：

| 方法 | 23 轮 log₂ 最大概率 | 判断 |
|---|---:|---|
| 原窗口评分策略 | -66.510008 | 新实现基准 |
| 8 个局部候选，按下一轮总质量选窗 | -66.394698 | 提高约 0.115 bit |
| 8 束窗口历史，每束最多 8 个候选，按峰值剪枝 | **-66.288552** | 提高约 0.221 bit |
| 真实单比特边缘分布选窗 | 第 18 轮无路径保留 | 明显更差 |

束搜索返回单个胜出历史，不对重叠历史的概率相加；胜出历史用单历史 CLI 重放后，所有轮的最大概率完全一致。它只证明这次配置有改进，不保证其它输入或轮数更好。边缘分布策略的失败也说明高维相关性不能仅靠逐比特信息刻画。

## 验证与限制

初版 12 项自动测试通过：16 位穷举差分分布、16 位 Walsh 谱、五种字长和两种密码及两种模式的完整短窗 CPU/GPU 对照、随机稠密差分、消元缺陷回归、大交空间上的均匀分布、窗口索引、嵌套性质和日志校验。三个 CUDA 内核共享基构造代码；它们是不同转移实现，不等于三个完全独立的密码分析程序。

修正前的原型记录和因资源预算中止的实验放在 `results/prototype/`，不作为最终结论的依据。没有进行最新文献的全面排查、真实 SIMON 45 轮的明文对统计或密钥恢复实验，因此这里不宣称新的公开最佳纪录。


## 后续硬件优化

在保持共享训练环境的条件下，进一步实现仿射查表、无原子陪集归约、分层位统计、融合输出统计、双缓冲和 NVLink 多卡分片。单卡完整流程相对提交 `0f62945` 的三组交替实测中位数加速 **4.28 倍**。详情及原始数据见 [硬件优化记录](hardware-optimization.md)。这批优化保持原窗口概率，不引入新的密码分析轮数结论。


## 八卡动态扩窗到 w17

后续已实现跨卡选窗，不再仅能重放。SIMON128 差分 45 轮由 w16 的 −127.761229169588 改善到 **−127.725579424791**，提高约 0.03565 bit（2.50%）；线性 46 轮由 −131.35119885446 改善到 **−131.290195661**，仍未超过 2^-128。差分与线性均保存完整计划和另一内核复核。详见 [分布式搜索记录](distributed-search.md)。本轮未增加轮数。
