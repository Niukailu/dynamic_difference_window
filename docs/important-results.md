# 论文初始点的新版结果复核

本次覆盖用户表格中的 15 个初始点：SIMON64 六项、SIMON96 四项、SIMON128 四项、SIMECK64 一项。README 仅汇总最终结果，具体计算条件和可复核证据放在这里。

## 比较口径

每项以原始 `experiments/*_PRECISION_14/info.log` 为起点。取日志最后一轮：这 15 份记录的最后一轮均是首次低于论文采用的 `2^−分组长度` 阈值的轮次。因此直接比较同一输入、同一轮数的旧权重与新权重，可以判断是否至少推进一轮。输出端点可由搜索选择；不把不同输出的权重相加。

旧值来自原始日志，保留其六位小数。先由当前 Rust/CUDA 重放旧窗口，单独记录历史值与重放值的差异，再进行搜索。历史程序数值与现实现有差异，超过舍入误差的部分不能归为算法优化收益。`historical_replay_max_error` 记录逐轮最大差异，原始数据不被覆写。

## 统一计算流程

1. 导入旧窗口并按线性模式的物理左右分支约定转换，重放全部轮次。
2. 以重放计划为起点，做两遍最终端点引导的坐标优化，窗口宽度 14。
3. 对选出的完整计划嵌套扩为宽度 16，作为参考路径集合 A。
4. 以窄计划为候选 B，在中间相邻两轮进行联合选窗，优化 `P(B\A)`。每个窗口的候选池为 16；这是有限邻域搜索，不是全局最优。
5. 用非负标签重放 B 的新增路径，另做普通 B 重放和 B∩A 重放，验证 `P(B)=P(B∩A)+P(B\A)`。最终报告 `P(A∪B)=P(A)+P(B\A)`，并与普通扩窗结果核对。

每卡串行执行一个完整案例，八卡并行分配不同案例。原生密码计算全部为 Rust/CUDA；`tools/important_suite.py` 仅负责调度、记录和检查。每进程 GPU 分配预算 52 GiB，主机反向缓存预算 128 GiB。运行时有其他训练负载，耗时不作为独占速度比较。

本批统一流程不自动替代此前更大窗口或不同搜索预算的最好结果。特别是 SIMON128 差分和 SIMON64 线性已有更宽窗口的记录；汇总时应保留更好的已验证结果，并明确来源。

## 原始证据

- `results/exploration/important-suite/manifest.json`：原生程序提交与二进制 SHA-256、运行器 SHA-256、完整案例清单及预算。
- 各案例 `original.jsonl`、`replay.jsonl`：历史窗口及新版复核。
- 各案例 `refined.jsonl`、`expanded.jsonl`、`novel.jsonl`：完整优化计划与新增路径、交集、并集权重。
- 各案例 `commands.json` 和阶段日志：实际命令、成功/失败状态与耗时。
- 各案例 `summary.json` 与总 `summary.json`：最终分数、阈值判断与历史差异。

这些是 FP64 论文路径聚集模型下的数值验证；线性模式为平方相关路径权重，不是固定密钥带符号相关性的直接实验。

复现整批实验（输出目录必须不存在）：

```bash
PYTHONPATH=. python tools/important_suite.py \
  --binary ./target/release/ddw --output results/my-important-suite
PYTHONPATH=. python tools/check_important_results.py \
  results/my-important-suite --output results/my-important-checks.json
```

命令默认使用八张卡，每个案例完成后立即保存汇总；任一阶段失败会保留日志并在最终退出时报告，不能把不完整任务记为成功。

## 最终结果

15 项统一流程全部完成，随后针对接近阈值的 SIMECK64 差分补做宽度 18 的扩展。共检查 61 份完整新计算记录；所有新增路径并集通过独立标量恒等式复核，15 个最终选用值也逐一核对了来源、输入、方法、端点和差值。历史重放按原日志六位小数精度检查；后续原生结果采用更严格的数值容差。见[审计文件](../results/validation/important-suite-checks.json)。

本轮新确认三个初始点达到更多轮：

| 初始点 | 方法 | 原先达到 | 本次达到 | 新一轮 log₂ 权重 |
|---|---|---:|---:|---:|
| SIMON64 `(0x40000004, 0x1)` | 线性 | 23 | 24 | −63.937635560048 |
| SIMON96 `(0x4000, 0x11101)` | 差分 | 32 | 33 | −95.407092382432 |
| SIMECK64 `(0x0, 0x1)` | 差分 | 31 | 32 | −63.936069770854 |

这里“达到”指论文模型下超过阈值，不证明更高轮数不可能，也不宣称公开文献新纪录。SIMECK64 的最终值来自单个宽度 18 的完整计划，不将宽度 16 的新增量直接加到它上面。

README 采用每个初始点的已验证最好结果，而非强制使用本次统一预算的最后输出。三项保留此前更强记录：SIMON64 线性 `(0x44400, 0x1000)` 的 25 轮并集、SIMON128 差分 `(0x1000, 0x4440)` 的 45 轮宽窗结果，以及 SIMON128 线性 `(0x4000000000000044, 0x1)` 的 46 轮宽窗结果。这三项的补跑已完成，但没有超过原最好值；不能声称本次用更小预算重新达到了旧最好值。

[最终清单](../results/best/important-results.json)对每项保存选用来源、指标、目标端点、本次统一流程分数和对应汇总文件。SIMON128 差分 45 轮是此前已经达到的结果，不计入本轮新增的三个初始点。
