# 实现结构

`src/main.rs` 定义 CLI；`model.rs` 定义窗口、密码配置与 JSONL 计划；`run.rs` 组织逐轮搜索、重放、扩窗和结果验证。外部输入输出始终采用真实左右分支顺序，线性模式只在内部交换分支。

`engine.rs` 组织单卡计算：构造一轮 GF(2) 仿射空间，限制到右窗口，生成陪集计划，对输入行归约，再通过分块仿射查表生成输出并同步计算统计量。工作区按名称复用，概率矩阵在相邻轮次复用。每轮按峰值归一化，并累计 log₂ 尺度，减少下溢。

`cuda.rs` 集中封装 CUDA Driver API 与 NVRTC 的 FFI。设备缓冲持有主上下文引用并在释放时归还显存预算；每次线程切换后激活对应上下文。Rust 不把设备地址转换为可解引用的主机引用。NVRTC 编译按密码参数和实际架构专门化，转移源码嵌入二进制；当前每次启动编译一次，没有持久化 PTX 缓存。

`cuda/kernels.cu` 为 Rust 和 Python 对照共享的转移内核；`cuda/runtime.cu` 提供 GPU 前缀扫描、行质量、转置、矩阵归一化、位统计和 peer 重排。独立 CPU 数学参考不依赖这些内核，保留检验共同内核错误的能力。

`multi.rs` 用 Rust scoped threads 调度各卡：输入按左窗口高位分行，每张卡算出不相交的输出列；随后读取各卡列片并生成下一轮行片，交换同时归一化。全局候选统计和质量只汇总小型标量数组。矩阵主体不经主机。小于设备数的窗口可以回退到首卡。

`refine.rs` 固定最终端点，在主机保存反向权重，用三轮局部重放与 suffix 点积评估一次窗口替换。每次保留原窗口作为候选，只接受终点分数增加的修改；每个 sweep 结束再次检查不下降。该方法是局部坐标优化，并非全局最优搜索。

JSONL 保存完整窗口、概率峰值、总质量、输出端点、设备列表、源码哈希和计时。启动编译计入 `setup_seconds`；逐轮时间计入搜索，独立记录选窗、转移和交换。`validate --reference` 是等值回归；扩窗运行还保存旧端点上的新权重，供不下降检查。历史日志缺少完整配置时仅补齐可推导的轮数，不猜测截断数据。

后续性能优化应以完整流程实测为依据：持久工作线程、减少 Driver API 调用与分配同步、NVRTC 缓存、融合归一化等仍有空间。更换主机语言本身不改变核心 CUDA 转移复杂度，也不能直接保证突破轮数。

新的 `compressed.rs` 组织无损隐式状态的固定重放/嵌套扩窗，`cuda/implicit.cu` 在虚拟元素上执行归约，并缓存边缘统计。`posterior.rs` 利用前向与伴随后向消息批量评价窗口换位；`union.rs` 用完整容斥计算同端点路径并集。详见[后续实现与验证](implicit-search.md)。
